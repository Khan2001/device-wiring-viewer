# 机房设备二维可视化编辑器

## 1. 文档信息

- 文档类型：需求规格说明书与技术实现路线图
- 版本：0.1
- 产品形态：基于浏览器访问的 Web 应用
- 部署方式：Docker Compose
- 目标用户：机房运维人员、网络管理员、设备交接人员
- 参考产品：[nVisual Viewer](https://github.com/nvisual-viewer/nvisual-viewer)

## 2. 产品目标

建立一套轻量的机房设备可视化台账，使维护人员能够通过二维图形快速了解：

1. 机房中有哪些机柜以及机柜位置。
2. 每个机柜中安装了哪些设备。
3. 每台设备有哪些接口。
4. 哪些接口之间存在连接。
5. 设备、接口和连接分别有什么备注。
6. 如何根据系统中的信息在正式环境中定位对应设备。

系统不进行真实网络协议、数据包、电气或三维物理仿真。系统中的“仿真”仅用于表达设备外观、接口和连接关系。

## 3. 设计原则

### 3.1 数据优先

二维图只是数据的一个视图。机柜、设备、接口和连接必须以结构化数据保存，不能只保存为不可查询的图片或画布文件。

### 3.2 简单可维护

第一版只实现实际交接和维护所需功能，不实现三维模型、自动发现、复杂网络模拟和多人实时协作。

### 3.3 层级清晰

采用类似 nVisual 的层级浏览方式：

```text
项目
  └─ 机房
      └─ 机柜
          └─ 设备
              └─ 接口
```

### 3.4 每个对象都可定位

设备名称、机柜编号、U 位、接口名称和连接名称应具有明确的现场对应关系。

## 4. 范围

### 4.1 MVP 范围

- 用户登录
- 项目管理
- 机房管理
- 机房二维平面图
- 机柜管理和拖拽定位
- 机柜二维视图
- 设备管理

- 设备接口管理
- 接口之间创建和删除连接
- 设备、接口、连接备注

- 数据持久化
- Docker Compose 部署
- 基础搜索
- JSON 数据导出

### 4.2 暂不实现

## 5. 用户角色

### 5.1 管理员

- 登录系统
- 创建、修改、删除项目
- 创建、修改、删除机房、机柜、设备和接口
- 创建、修改、删除连接
- 修改所有备注
- 导出和备份数据

### 5.2 普通用户

MVP 默认允许查看全部信息，可选地允许编辑备注和连接。删除操作只开放给管理员。

## 6. 功能需求

### FR-001 用户登录

- 用户通过浏览器访问系统。
- 未登录用户不能查看项目数据。
- 登录状态应支持有效期控制。
- MVP 可以使用本地用户名和密码。
- 后续可接入 LDAP、OIDC 或企业统一认证。

### FR-002 项目管理

项目用于隔离不同机房或不同客户的数据。

项目字段：

- 项目名称
- 项目标识
- 描述
- 创建人
- 创建时间
- 修改时间

支持：

- 新建项目
- 修改项目
- 删除空项目
- 打开项目
- 导出项目

### FR-003 机房管理

机房字段：

- 名称
- 编号
- 地址或位置描述
- 宽度和高度
- 背景图，可选
- 备注

支持：

- 在机房中添加机柜。
- 拖动机柜。
- 网格吸附。
- 机柜编号显示。
- 点击机柜进入机柜视图。

### FR-004 机柜管理

机柜字段：

- 名称
- 编号
- 高度，默认 42U
- 宽度
- 深度
- 所在机房
- 平面图坐标
- 正面/背面方向
- 备注

支持：

- 新建机柜。
- 编辑机柜。
- 删除空机柜。
- 在平面图中拖动机柜。
- 进入机柜视图。
- 查看机柜中的设备和空闲 U 位。

### FR-005 设备管理

设备字段：

- 名称
- 编号或资产编号
- 对象类型
- 设备分类
- 厂商
- 型号
- 序列号，可选
- 管理地址，可选
- 所属机柜
- 起始 U 位
- 占用高度
- 正面或背面
- 设备颜色
- 备注
- 设备图片，可选

#### 设备字段设计

不建议让所有对象共用完全相同的字段。系统应采用“通用字段 + 分类字段”的方式：

```text
通用字段：
  名称、编号、分类、厂商、型号、状态、位置、备注、图片

网络设备字段：
  管理 IP、MAC 地址、登录地址、设备角色、接口数量

光纤/网线字段：
  线缆编号、线缆类型、长度、芯数、接头类型、颜色、起点、终点

机柜设备字段：
  起始 U 位、占用高度、正面/背面、安装方式
```

#### 设备通用字段

所有可管理对象建议具备以下字段：

| 字段 | 必填 | 说明 |
|---|---:|---|
| 名称 | 是 | 人员易读的名称，例如“核心交换机-01” |
| 对象类型 | 是 | 设备、线缆、配线架、模块、其他 |
| 设备分类 | 是 | 路由器、交换机、服务器、光纤、网线等 |
| 编号 | 是 | 资产编号、设备编号或线缆编号 |
| 厂商 | 否 | Cisco、华为、康普等 |
| 型号 | 否 | 设备型号或线缆规格 |
| 序列号 | 否 | 设备序列号；线缆通常不填写 |
| 状态 | 是 | 在用、备用、故障、停用、待报废 |
| 所属机房 | 是 | 当前所在机房 |
| 所属机柜 | 否 | 机柜设备填写，线缆可不填写 |
| 责任人 | 否 | 维护责任人或部门 |
| 安装日期 | 否 | 投入使用或安装日期 |
| 最后巡检时间 | 否 | 最近一次确认现场状态的时间 |
| 备注 | 否 | 多行文本 |
| 图片 | 否 | 设备照片、面板照片或现场位置照片 |

#### 路由器、交换机等有源设备字段

建议在通用字段之外支持：

| 字段 | 说明 |
|---|---|
| 设备角色 | 核心、汇聚、接入、出口、管理等 |
| 管理 IP | 用于现场管理和定位 |
| MAC 地址 | 设备或管理口 MAC |
| 主机名 | 网络设备配置中的 hostname |
| 软件/固件版本 | 便于维护时确认版本 |
| 电源数量 | 例如单电源、双电源 |
| 额定功率 | 可选，仅做信息记录 |
| 设备尺寸 | 宽度、深度、高度 |
| 默认接口模板 | 新建设备时自动生成接口 |
| 登录地址 | 可以是管理 URL；密码不在本系统中保存 |

管理 IP、MAC 地址和主机名应支持搜索。设备图片至少支持上传一张，也可以支持多张并标记为“正面”“背面”“铭牌”“安装位置”。

#### 光纤、网线等线缆字段

光纤和网线不建议完全建模成机柜设备，而应作为线缆对象或连接对象管理：

| 字段 | 必填 | 说明 |
|---|---:|---|
| 线缆编号 | 是 | 现场标签，例如 `FO-001`、`UTP-024` |
| 线缆类型 | 是 | 单模光纤、多模光纤、Cat5e、Cat6、Cat6A 等 |
| 长度 | 否 | 例如 3m、10m |
| 颜色 | 否 | 便于现场识别 |
| 芯数/对数 | 否 | 光纤芯数或双绞线对数 |
| 接头类型 | 否 | LC、SC、FC、RJ45、MPO 等 |
| 起点接口 | 是 | 连接的起始端口 |
| 终点接口 | 是 | 连接的目标端口 |
| 铺设路径 | 否 | 机柜内、机柜间、桥架、地板下等 |
| 状态 | 是 | 在用、备用、故障、拆除 |
| 备注 | 否 | 例如“走上方桥架，标签不清晰” |
| 图片 | 否 | 线缆标签、端头、走线路径照片 |

光纤还可以增加：

```text
单模/多模
波长
芯数
两端模块类型
是否为备用芯
```

网线还可以增加：

```text
Cat5e/Cat6/Cat6A
屏蔽/非屏蔽
长度
水晶头或模块类型
```

#### 配线架、光纤盒和模块字段

这类对象不是有源网络设备，也不是普通线缆，建议作为独立设备分类：

```text
配线架：
  端口总数、安装高度、面板类型、端口编号规则

光纤配线架/光纤盒：
  盘纤容量、光纤芯数、适配器类型、熔纤盘数量

模块：
  模块类型、接口类型、兼容设备、安装位置
```

支持：

- 在机柜中新增设备。
- 修改设备信息。
- 拖动设备调整 U 位。
- 修改设备占用高度。
- 检测设备 U 位重叠。
- 删除设备前检查是否存在接口连接。
- 点击设备查看详细信息。

### FR-006 接口管理

接口字段：

- 接口名称，例如 `eth0`、`GE1/0/1`
- 接口类型，例如网口、光口、电源口、串口
- 接口编号
- 接口位置
- 接口方向，可选
- 接口状态
- 备注

支持：

- 添加接口。
- 修改接口。
- 删除未连接接口。
- 批量生成接口。
- 在设备二维面板上显示接口。
- 按接口名称或类型排序。

### FR-007 接口连接

连接字段：

- 连接名称
- 起始接口
- 目标接口
- 连接类型
- 线缆编号
- 线缆颜色
- 线路状态
- 备注
- 画布路径，可选

支持：

- 从一个接口拖拽到另一个接口。
- 创建连接前检查起点和终点是否有效。
- 显示连接方向或双向标记。
- 点击连接查看两端设备和接口。
- 修改连接属性。
- 删除连接。
- 高亮某个设备或接口的所有连接。
- 查看一个设备的直接连接对象。

MVP 不要求实现自动避障路线。设备移动后，连接线可以自动使用起点和终点之间的折线重新绘制。

### FR-008 备注和附件

设备、接口、机柜和连接都支持备注。

备注应支持：

- 普通文本
- 多行文本
- 修改时间
- 最后修改人

附件支持可选实现：

- 图片
- PDF
- 文本配置文件

附件必须保存到服务器持久化目录，不能只存容器临时目录。

### FR-009 画布操作

支持：

- 鼠标拖动平移
- 滚轮缩放
- 适配全部对象
- 框选
- 单击选中
- 双击进入下一级视图
- Delete 删除当前选中对象
- Ctrl/Cmd+Z 撤销
- Ctrl/Cmd+Shift+Z 重做
- Ctrl/Cmd+S 保存

界面必须提供当前保存状态：

```text
已保存
保存中
保存失败
```

### FR-010 搜索

支持按以下字段搜索：

- 机柜名称或编号
- 设备名称或资产编号
- 接口名称
- 连接名称
- IP 或管理地址
- 备注内容

搜索结果可以定位到对应机房、机柜、设备或接口，并在画布中高亮。

### FR-011 导出和备份

支持：

- 导出项目 JSON
- 导出当前视图 PNG
- 导出当前视图 SVG
- 导入项目 JSON

导入前应校验数据格式，并提示将要覆盖或合并的内容。

## 8. 数据模型

建议使用 PostgreSQL，MVP 也可以使用 SQLite 进行单机部署。

### 8.1 核心表

```text
projects
rooms
cabinets
devices
ports
connections
        └─ cable fields for physical cable information
view_items
attachments
users
```

### 8.2 关系

```text
Project 1 ── N Room
Room 1 ── N Cabinet
Cabinet 1 ── N Device
Device 1 ── N Port
Port 1 ── N Connection
```

### 8.3 关键约束

- 设备必须属于一个机柜或处于未安装状态。
- 接口必须属于一个设备。
- 连接的起始接口和目标接口必须存在。
- 连接不能连接到自身。
- 设备的 U 位不能超出机柜范围。
- 设备之间不能发生 U 位重叠。
- 删除设备前必须处理它的接口和连接。
- 删除接口前必须确认该接口没有连接。

## 10. 技术实现方案

### 10.1 前端

- Vue 3
- TypeScript
- Vite
- SVG 二维画布
- `d3-zoom` 或自定义 Pointer Events 实现平移和缩放
- Pinia 管理编辑状态
- TanStack Query 或等价方案管理服务端数据
- Element Plus 或 Naive UI 提供基础界面组件
- VueUse 或等价方案提供常用交互工具
- Vue 表单组件管理属性表单

初版采用 SVG，不使用 Three.js。SVG 中的机柜、设备、接口和连接线都是独立元素，适合实现选择、点击、拖动、端口连线、文字显示和导出。

### 10.2 后端

推荐：

- FastAPI
- SQLAlchemy
- Alembic
- Pydantic
- PostgreSQL

后端负责：

- 身份验证
- 权限检查
- 数据校验
- 事务保存
- 搜索
- 导入导出
- 文件上传

### 10.3 数据库和文件

- PostgreSQL 保存结构化数据。
- 文件附件保存到 `/app/uploads`。
- Docker Volume 持久化数据库和附件。
- JSON 是导入导出格式，不作为线上主存储。

### 10.4 Docker 部署

```text
reverse-proxy
  └─ app
      ├─ Vue 静态文件
      └─ FastAPI API
  └─ postgres
```

至少需要：

- `app` 镜像
- `postgres` 镜像
- 数据库 Volume
- 附件 Volume
- 环境变量配置
- 健康检查
- 数据库备份脚本

## 11. 非功能需求

### NFR-001 可部署性

- 支持 Linux 服务器。
- 支持 Docker Compose。
- 新服务器安装 Docker 后可以完成部署。
- 所有数据必须通过 Volume 持久化。

### NFR-002 浏览器兼容性

支持当前版本的 Chrome、Edge、Firefox、Safari。

### NFR-003 性能

MVP 目标：

- 单个项目支持至少 100 个机柜。
- 单个机柜支持至少 100 台设备。
- 单个项目支持至少 5000 个接口。
- 常规画布操作保持可用。
- 页面初次加载目标不超过 3 秒，具体取决于服务器和数据量。

### NFR-004 数据安全

- 密码不能明文存储。
- API 必须检查登录状态。
- 删除操作需要二次确认。
- 数据库应支持定期备份。
- 生产环境使用 HTTPS。

### NFR-005 可维护性

- 前端、后端、数据库迁移分层。
- API 使用 OpenAPI 文档。
- 核心数据模型有自动化测试。
- 所有删除和保存操作有日志。

## 12. 验收标准

### AC-001 机柜和设备

能够在浏览器中创建一个 42U 机柜，添加设备，设置设备从 U20 开始占用 2U，并重新打开页面后仍保持位置和属性。

### AC-002 接口和连线

能够给交换机添加 `GE1/0/1`，给服务器添加 `eth0`，从一个接口拖线到另一个接口，保存后刷新页面，连接仍然存在。

### AC-003 备注

能够给设备和连接添加备注，保存后在详情面板和搜索结果中看到。

### AC-004 约束校验

不能把设备放到超出机柜高度的位置，不能创建不存在接口之间的连接，不能删除仍有连接的接口而不处理连接。

### AC-005 Docker

在干净的 Linux 服务器上执行 Docker Compose 部署后，用户可以通过浏览器访问系统并完成以上全部操作。

### AC-006 数据持久化

重启应用容器和数据库容器后，机柜、设备、接口、连接、备注和布局数据不丢失。

### 13.1 推荐的最小实现顺序

为了尽快得到可使用的版本，建议按照以下顺序开发：

```text
1. Docker Compose、数据库迁移和健康检查
2. 项目/机房/机柜/设备/接口/连接 API
3. Vue 页面和右侧属性编辑面板
4. 机房 SVG 画布和机柜拖动
5. 机柜 SVG 视图和设备 U 位布局
6. 设备 SVG 面板和接口显示
7. 端口拖拽连线
8. 自动保存、错误提示和搜索
9. JSON/PNG/SVG 导出
10. 备份、权限和生产部署
```

第一版不要同时开发三维模型、自动布线和复杂权限。先完成“创建机柜 → 添加设备 → 添加接口 → 连线 → 保存 → 刷新后恢复”的闭环。

### 13.2 二维画布内部设计

建议为每种对象建立独立的 Vue 组件：

```text
RoomCanvas.vue
CabinetNode.vue
DeviceNode.vue
PortHandle.vue
ConnectionLine.vue
SelectionOverlay.vue
```

画布状态至少包含：

```ts
{
  selectedObjectId: string | null,
  viewMode: 'room' | 'cabinet' | 'device',
  zoom: number,
  pan: { x: number, y: number },
  isConnecting: boolean,
  connectionStartPortId: string | null,
  dirty: boolean,
  saveState: 'saved' | 'saving' | 'failed'
}
```

SVG 坐标和业务数据应分开：

- 设备的 `cabinetId`、`startU`、`heightU` 表示真实安装信息。
- 设备的 `x`、`y` 表示当前二维视图位置。
- 接口的 `x`、`y` 表示设备面板中的相对位置。
- 连接线的端点根据接口位置实时计算。

设备移动后，连接线自动重新计算。第一版不保存复杂的人工线路路径，避免设备移动后出现过期线路。

## 15. 最终产品边界

第一版的成功标准不是“模拟真实网络”，而是让维护人员能够回答以下问题：

```text
这个设备在哪个机房？
它在哪个机柜？
占用了哪些 U 位？
它有哪些接口？
每个接口接到了哪里？
这条线路的备注是什么？
我能否根据这些信息在现场找到真实设备？
```

只要上述问题都能在浏览器中快速回答，系统就达到了第一版目标。
