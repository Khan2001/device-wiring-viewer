# 机房设备二维可视化编辑器开发计划

> 当前进度：Iteration 0 至 Iteration 8 已完成基础实现。Iteration 9 继续补充图片管理、权限、备份和生产加固。

## 1. 开发目标

交付一个可以部署到服务器、通过浏览器使用的二维机房设备编辑器，完成以下闭环：

```text
创建项目
  → 创建机房
  → 创建机柜
  → 添加设备
  → 添加接口
  → 接口之间连线
  → 编辑备注和图片
  → 保存
  → 刷新后恢复数据
```

## 2. 技术基线

```text
前端：Vue 3 + TypeScript + Vite
UI：Element Plus 或 Naive UI
画布：SVG
状态：Pinia
缩放平移：d3-zoom 或 Pointer Events
后端：FastAPI
数据库：PostgreSQL
文件：服务器持久化目录
部署：Docker Compose
```

## 5. 前端状态设计

建议把状态分为三类：

### 5.1 服务端状态

由 TanStack Query 或等价方案管理：

```text
项目
机房
机柜
设备
接口
连接
```

### 5.2 画布临时状态

由 Pinia 管理：

```text
当前视图
当前选中对象
缩放比例
画布偏移
拖动状态
当前连线起点
```

### 5.3 编辑历史状态

用于撤销和重做：

```text
AddDeviceCommand
MoveDeviceCommand
UpdateDeviceCommand
AddConnectionCommand
DeleteConnectionCommand
```

第一版可以只在前端维护撤销栈，不要求数据库保存每一步操作。

## 6. 后端开发顺序

后端建议按照以下顺序实现：

```text
1. 配置和数据库连接
2. 数据库迁移
3. 基础模型和 CRUD
4. 关系校验
5. 统一错误返回
6. 登录认证
7. 文件上传
8. 搜索接口
9. 导入导出
10. 备份和日志
```

所有修改操作应使用事务。涉及设备、接口和连接的删除操作必须在后端再次校验，不能只依赖前端限制。

## 8. 风险和处理方式

### 风险 1：画布交互过早复杂化

处理：

- 第一版只实现矩形设备、圆形接口和折线。
- 不实现旋转、自由变形和自动避障。

### 风险 2：视图数据和业务数据混乱

处理：

- 设备、接口和连接使用独立数据库表。
- 坐标只作为布局数据保存。
- SVG 不直接作为数据源。

### 风险 3：设备类型字段不断增加

处理：

- 保留通用字段。
- 增加 `custom_attributes` JSONB 字段。
- 只有反复使用的属性才提升为正式字段。

### 风险 4：设备和线缆概念混淆

处理：

- 路由器、交换机、服务器作为设备。
- 光纤、网线作为线缆或连接属性。
- 配线架、光纤盒作为特殊设备。

### 风险 5：浏览器刷新导致数据丢失

处理：

- 增加自动保存。
- 显示保存状态。
- 页面离开前检测未保存状态。
- 后端保存成功后才清除前端 dirty 标记。

## 9. Definition of Done

一个功能只有同时满足以下条件，才算完成：

- 页面功能可操作。
- 数据通过 API 保存。
- 刷新页面后数据仍然存在。
- 错误情况有明确提示。
- 关键逻辑有测试。
- Docker 环境可以启动。
- 不影响已有功能。
- 相关接口和字段已更新文档。

## 10. 第一版交付标准

第一版最终应能完成以下演示：

```text
1. 登录系统
2. 新建“机房 A”
3. 在机房中创建“机柜 A01”
4. 将交换机放到 U40
5. 将服务器放到 U20
6. 给交换机生成 24 个接口
7. 给服务器添加 eth0 和 eth1
8. 将交换机 GE1/0/1 连接到服务器 eth0
9. 给设备和连接填写备注
10. 上传设备照片
11. 刷新浏览器
12. 数据、布局、连线和图片全部恢复
13. 导出当前视图
```
